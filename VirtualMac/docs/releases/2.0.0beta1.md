# Virtual Mac on iPad 2.0.0beta1

版本名称：`2.0.0beta1`。构建号和 Debian 包版本：`1001`。

这是个人 fork 的首个 2.0 测试版，使用独立应用标识
`com.mac.virtual.v2` 和运行库目录 `/var/root/VirtualMac2`，可与原版
1.2.3 共存。虚拟机磁盘继续保存在现有虚拟机目录中。
Debian 包保留对原版基础包的依赖，升级或清理测试应用时应保留原版 1.2.3
及其共享组件。

下载资产：`VirtualMac_2.0.0beta1_1001.deb`。支持的打包和安装方法见
[`virtualmac2-packaging.md`](virtualmac2-packaging.md)。

## 后端范围

当前可运行的组合保留 macOS 13.2.1 的 CPU、VMM 和 Virtualization
框架，接入 macOS 27 的 ParavirtualizedGraphics、GPU Task、
MetalSerializer 及应用私有着色器编译组件。完整 macOS 27 CPU/VMM/VZ
移植仍在开发，仓库内的独立 CPU/Swift 兼容实验不等于生产运行库已替换。

兼容代码在应用进程和应用私有运行库中工作，不修改 iPadOS 系统框架。
目前实机验证环境为越狱 M2 iPad、iPadOS 16.1.1，来宾为 macOS 26 Tahoe。
这不能推导出其它设备、驱动版本或来宾系统均已通过验证。

## 本版变化

- 增加现代 PVG 的来宾内存映射、IOSurface 描述符和独立 GPU Task
  传输兼容，保留真实 GPU 工作、事件完成和错误返回。
- 加入经过版本和字节校验的 PVG 界面配置，关闭可选共享纹理句柄，
  使用来宾已有的 Mac 能力配置。保留宿主物理 Metal 能力查询；
  不以声明 Apple8 替代缺失的资源寻址实现。
- `iconservicesagent` 和 `iconservicesd` 使用系统 Metal 能力路径，
  避免额外启用 Apple7 OpenGL 路径。其它受支持应用保留原 OpenGL 兼容。
- 修正来宾工具就绪确认的重试竞争；图标缓存修复等待缓存再生和稳定期后，
  才记录完成状态。
- 一个前端进程只启动一条输入轮询链，避免在多次启动来宾后重复轮询。
- 完整着色器输入采集改为明确启用：只有
  `VZ_PVG_SHADER_INPUT_AUDIT=1` 才采集。保留转换缓存、可选持久缓存和
  原生编译回退，减少正常运行中的同步诊断复制、哈希和文件写入。
- 补齐常规 VMM 构建路径依赖的项目桥接源文件，并在签名前检查这些符号
  确实由本库定义，防止动态查找掩盖构建遗漏。

## 打包前实机验证

同一修复组合已在上述 M2 iPad 的 Tahoe 来宾中验证：

- Finder、TextEdit、计算器和系统设置同时运行，菜单文字、状态栏和
  系统设置能耗图标在原生 USB 截图中显示正常。
- 自有 CoreImage 渲染探针的 8 项像素结果通过检查。
- 来宾工具安装状态、实际注入库、macOS 27 图形运行库和编译组件身份
  与已核验产物一致；持续观察约 25 分钟未产生新的用户 IconServices 崩溃。
- App 窗口出现时间已测量；窗口元数据出现不代表完整首帧或内容加载完成。

这些验证覆盖当时的操作路径，不能据此声称所有图标路径、完整 Apple8、
间接资源寻址或 EVE Online 场景渲染均已修复。

源码中的 `enable-guest-ssh` 是测试用的固定动作，它的附带状态检查包含
账户 `lkx`。使用其它来宾用户名时应调整这项诊断检查；已正常启用的
系统 SSH 服务不受这项检查限制。设备 SSH 密码不包含在源码或软件包中。

## deb 安装后的复验

- 实际安装 `com.mac.virtual.v2` 版本 `1001`，应用版本为
  `2.0.0beta1`，保留原版 1.2.3；两个旧测试应用已卸载。
- 原有 Tahoe3 正常启动并登录，永久 iPad `22222` 来宾 SSH 可用；
  来宾工具自动更新为 `1001-ea34391601f65d97`，图标兼容库身份保持一致。
- 新包的 82 项代码身份及完整文件哈希通过安装后核验，实际 VMM 与
  macOS 27 GPU Task 进程运行正常；8 项 CoreImage GPU 像素检查通过。
- 安装前后，原版全部文件哈希、三个来宾磁盘的 inode 与容量、来宾
  身份文件哈希，以及已有编译器的 inode、时间字段和持久缓存身份收据
  均保持一致。
- 独立安装检查通过 12 项停止状态保护、4 项编译器文件保留用例和
  4 项签名篡改拒绝用例。

独立 PVG 探针通过普通 SSH 启动时仍可能被 iPadOS 的文件映射沙盒阻止；
这条诊断入口没有作为实机运行通过的依据。实机图形验证使用实际来宾的
GPU 工作完成回调及像素结果。

## 开发与复现

现代后端构建入口为 `scripts/development/build-virtualmac2.sh`。
它需要匹配版本的 macOS 27 GPU Task 原件、已经转换和核验的框架输入，
以及工作正常的旧 CPU/VMM 运行库快照；原始系统固件和生成的 Apple 二进制
不提交到 Git。

PVG 界面配置的输入和产物校验方法见
[`prepare-modern-pvg-ui-profile.README.md`](../../scripts/development/prepare-modern-pvg-ui-profile.README.md)。
持久编译缓存的目标设备身份和无收据回退规则见
[`README-persistent-converter-cache.md`](../../scripts/development/README-persistent-converter-cache.md)。
其它设备不能复用本机的文件身份收据；没有有效收据时，可选持久缓存应保持关闭。

源码中的 Swift、LLVM 和 libmalloc 适配保留原许可证与来源记录，位于
`vendor/`。设备凭据、虚拟机状态、运行日志、原始固件、生成产物和本机诊断
证据目录均不属于源码提交范围。
